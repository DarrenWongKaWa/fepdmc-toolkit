# P1: exact-corrected delayed acceptance for the swap update

P1 adds a cheap first stage to the native swap of two phonon vertices in the
JJ driver (`update_swap` in `diagMC_JJ_updates.f90`, Method 0). Proposals
that the cheap stage rejects return before the expensive electron–phonon
vertex and environment work. A second stage restores the exact native
acceptance ratio, so the sampled target is unchanged.

- Python algebra: `fepdmc_toolkit.p1_da`
- Source adapter for the pinned FEP-DMC tree: `integration/p1/`
- Design and contract: [p1-adapter-design.md](p1-adapter-design.md)
- Benchmark result: [results.md](results.md)

## Method

**Native object.** The native acceptance for a swap is

```
P_accept = abs(Re M_new / Re M_old) * P_kchange
```

where `P_kchange` collects the cheap electron and phonon propagator ratios
(`Gel`, `Dph`) and `M` is the expensive matrix contraction. The weight in the
ratio is `abs(Re M)`, not the complex modulus `|M|`; tests reject `|M|`.

**Two-stage delayed acceptance** (Christen–Fox):

1. *Stage 1 (cheap).* Evaluate the propagator log-score
   `ell_hat_raw = log P_kchange` (one extra `cal_ek_int`, no electron–phonon
   vertex), clip it to ±ln 10 to form `ell_hat`, and draw `u1` from an
   auxiliary generator. If `log u1 >= min(0, ell_hat)`, reject and return
   before `cal_gkq` and the environment contraction.
2. *Stage 2 (exact).* Otherwise run the native contraction, take
   `ell_R = log P_accept`, draw the native `ran`, and accept if
   `log ran < min(0, ell_R - ell_hat)`.

Because the score is antisymmetric under the reverse move and clipping
preserves antisymmetry, the product of the two stage probabilities has the
native ratio, so the chain samples the native target. The reverse move is an
occupancy reverse: exchange the two phonons' frequencies and partner times at
fixed time order and exchange the mid-band energies in the score. Flipping
both Δτ and ΔE is wrong and is rejected by the tests.

P1 does not change the Hamiltonian, the observable or the weight. The cheap
score never replaces the exact target.

## Use the adapter

```bash
python tools/verify_fep_dmc_upstream.py ./FEP-DMC
python integration/p1/apply_p1.py --tree ./FEP-DMC --dry-run
python integration/p1/apply_p1.py --tree ./FEP-DMC
python integration/p1/verify_p1.py --tree ./FEP-DMC
```

Then build Perturbo as usual and run with `LINEAR_DA=on`. C0 then P1, or P1
then C0, yield the same `PUBLIC_C0_P1_APPLIED` file hashes
([provenance/P1_PUBLIC_PATCH.json](../provenance/P1_PUBLIC_PATCH.json)).

| environment variable | default | values |
|---|---|---|
| `LINEAR_DA` | `off` | `off`, `on` |
| `LINEAR_DA_AUX_SEED` | `9142871` | nonzero 64-bit integer |
| `LINEAR_DA_SCORE` | `prop` | `prop` only |

With `LINEAR_DA=off` the patched binary uses no auxiliary random numbers and
no extra `cal_ek_int`, and the swap accepts with the native `ran < P_accept`.
At the end of a run the patched driver prints `LINEAR_DA_COUNTS` (mode, score,
counters and auxiliary seed). With P1 on, the counters satisfy
`n_s1_reject + n_expensive = n_eligible` and `n_expensive = n_accept + n_s2_reject`.

**Operating domain.** `LINEAR_DA=on` stops with an error for
`DMC_Method /= 0`, `dmc_band /= 1`, `sample_gt = .true.`,
`zeroTMC = .false.`, a score other than `prop`, or a `LINEAR_DA` value other
than `off`/`on`. `Re(M_old) = 0` with P1 on is also an error stop, where the
native code would accept with an infinite ratio.

## Native validation of the adapter

Kernel-level evidence on a short public JJ fixture
([validation/p1/NATIVE_VALIDATION.json](../validation/p1/NATIVE_VALIDATION.json)):

- Build: Ubuntu 22.04, gfortran 11.4 with OpenMPI, QE 6.5, plus build
  fixes unrelated to P1 (an MKL random-number shim and gfortran compatibility
  edits, listed in the record).
- Public LiF-electron dataset (`lif-sp3_epwan.h5`, SHA256
  `4960618b64f4f1787e7a30aac4c2990ec5632ecbab83a9632f6c659f03da690b`),
  `calc_mode=diagmc-JJ`, `zeroTMC=.true.`, T = 1000 K so that
  `tauMax ≈ 11.6 eV⁻¹`, SVD + `tabulate-H` with nk = 20, nsvd = 20,
  `Nmcmc = 1` (10⁴ steps), seed `P1_VALIDATE_SEED=12345`.
- Shown: the pinned FEP-DMC builds with the adapter; P1 off reproduces the
  pristine JJ update and acceptance counts; with P1 on, stage-1 rejects skip
  `cal_gkq*`; stage 2 uses the native `P_accept`; the counters close;
  unsupported domains stop.
- At T = 50 K the same dataset gives `tauMax ≈ 232 eV⁻¹`, and the native
  `Gel = exp(-ek*tau)` underflows in both numerator and denominator of
  `P_kchange` (`exp(-1186)`), so vanilla computes `P_accept = NaN` and P1
  stops by design. That is why the fixture uses 1000 K.

Not shown by this fixture: production statistics at 50 K, a wall-clock gain,
finite temperature, multiband or other DMC methods.

## Benchmarked build

The LiF timing benchmark in [results.md](results.md) used an earlier build of
the same algorithm, with profiling timers and a fixture switch. Its Fortran is
kept as a reference under `src/fepdmc_toolkit/fortran/`
(`linear_da_mod.f90`, `update_swap_p1_excerpt.f90`, `closure_observer.f90`).
It is not the module the adapter installs; the adapter's module is
`integration/p1/linear_da_mod.f90`.

In that build, `P1_FIXTURE=1` enabled an event-level check on LiF: 4372
stage-1 rejects with recorded electron–phonon and environment increments of
zero, and 6350 accepted-swap reverse checks. The timed runs used
`P1_FIXTURE=0`.
